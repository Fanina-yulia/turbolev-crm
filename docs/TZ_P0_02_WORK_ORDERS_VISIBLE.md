# P0-02 — Видимий контур «Наряди та ремонт»

## Мета

Відокремити виробничий WorkOrder від документа погодження. У головній навігації та робочому екрані користувач бачить «Наряди та ремонт». «Комерційна пропозиція» залишається назвою документа кошторису/погодження всередині наряду, а не назвою всього процесу.

## Контракт

- canonical route slug: `work-orders`;
- visible label: `Наряди та ремонт`;
- legacy labels: `Комерційна пропозиція`, `Замовлення-наряди`, `Виробництво`, `Контроль якості`, `Гарантії`;
- legacy labels нормалізуються в той самий slug і не створюють нової сутності або дубльованого WorkOrder;
- `WorkOrder.id` і номер `ЗН-xxxxxx` не змінюються;
- вкладка `estimate` відображає окрему КП, вкладки `works/parts/qc/payment/history` працюють у межах того самого наряду.

## UI acceptance

1. У групі «Сервіс» є один пункт «Наряди та ремонт».
2. Заголовок сторінки, aria-label, empty states, search placeholder і повідомлення використовують «наряд/наряди», а не misleading «Комерційна пропозиція».
3. Переходи з діагностики, планувальника, складу, QC, оплат, гарантії, картки авто та аналітики відкривають той самий `work-orders` route.
4. Старі deep links із legacy label/slug відкривають той самий екран і зберігають `workOrderId/status/workOrderTab`.
5. Прямий ремонт без ДК і КП залишається допустимим: екран наряду показує «Діагностична карта не застосовується», а не створює порожню КП.
