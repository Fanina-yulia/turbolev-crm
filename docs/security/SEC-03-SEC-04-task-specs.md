# SEC-03 / SEC-04 — окремі завдання (підготовлено паралельно з SEC-R1)

Статус: ПЛАН. Код не змінювався. Кожне завдання виконується в окремій гілці/PR після погодження власника.
Правила ті самі, що й для SEC-R1: сесія — єдине джерело особи; 401/403/404; без зміни фінансових формул; без небезпечних міграцій.

## Нова знахідка під час SEC-R1 (SEC-16, закрито частково в цій гілці)
`/api/qc` (черга QC) перевіряв доступ лише в режимі ENFORCED; за замовчуванням (SHADOW) був відкритий, а PASS/FAIL/MOVE_* оминали розділення функцій.
У SEC-R1: fail-closed у всіх режимах + `requireQcApproval` для PASS/FAIL/MOVE_*. START/RECHECK/GET лишаються за QC.READ/QC.WRITE.

## SEC-03 — персональні дані та фінансові операції (пріоритет 1)
Охоплення (перелік перевірити скриптом сканування маршрутів на момент старту — не покладатися на цей список як на вичерпний):
- клієнти/авто/історія: `api/clients*`, `api/client-card*`, `api/vehicles*`, `api/clients-vehicles`
- комунікації та вкладення: `api/communications/**` (зокрема `communications/attachments`), `api/leads/**`, `api/intake`
- фінанси/оплати/зарплата: `api/finance/**`, `api/payments`, `api/work-orders/[id]/payments`, `api/work-orders/[id]/finance/**`, payroll/personnel (документи, компенсації)
Робота: для кожного маршруту — permission з `api-policy.ts` + row-scope (`authorizeScopedLocation` / `canAccessWorkOrder`), actor лише із сесії, редакція чутливих полів без права, тести за схемою SEC-R1 (8 категорій).
Критерій готовності: жоден маршрут із ПІБ/телефоном/VIN/сумою не відповідає без сесії; `check-critical-api-security.mjs` містить усі ці маршрути.

## SEC-04 — ціни, налаштування, довідники (пріоритет 1)
- `api/settings/operations` (сирий SQL — окремо перевірити параметризацію), `api/settings/work-prices/*`, `api/work-prices`
- `api/workflow/presentation`, `api/planner/edit-context`
- довідники: каталоги робіт/запчастин/постачальників, словники статусів
Робота: запис — лише `SETTINGS_*`/`PARTS_WRITE`/`PROCUREMENT_WRITE` з відповідним scope; зміни цін та налаштувань пишуть AuditEvent (до/після, особа із сесії); читання публічних довідників — явно задокументоване винятком.
Критерій готовності: зміна ціни/налаштування без прав неможлива (401/403); кожна зміна має запис аудиту.

## Порядок
SEC-R1 (ця гілка) → SEC-03 → SEC-04 → SEC-05..15 за Security Remediation Plan. Жоден виявлений критичний маршрут не виключається; нові знахідки додаються сюди.
