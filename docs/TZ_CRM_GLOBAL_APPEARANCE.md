# Технічне завдання: глобальне оформлення CRM Turbo LEV

Версія: 1.0
Дата: 02.09.2026
Статус: реалізовано в поточній версії CRM
Відповідальний модуль: `Налаштування → Оформлення`

## 1. Мета

Надати адміністратору CRM єдиний центр керування зовнішнім виглядом усієї системи. Будь-яка збережена зміна повинна застосовуватися централізовано до всіх сторінок і робочих кабінетів CRM, а не лише до поточного браузера або одного маршруту.

Оформлення має підтримувати:

- готові стилі, які застосовуються одним натисканням;
- фірмову кольорову гаму Turbo LEV;
- розмір тексту, шрифт, щільність блоків і радіус карток;
- світлий, темний і системний режим;
- розгорнуту або компактну бічну навігацію;
- завантаження власного логотипу;
- живий попередній перегляд до збереження;
- серверне збереження та синхронізацію між користувачами й пристроями.

## 2. Межі робіт

### У межах релізу

1. Новий глобальний профіль `appearance` у наявній таблиці `CrmSetting`.
2. API читання та збереження профілю: `GET/PUT /api/settings/appearance`.
3. Клієнтський bridge у кореневому layout, який завантажує профіль на кожній сторінці.
4. Ранній bootstrap із кешу, щоб не було миготіння стилю під час завантаження.
5. Семантичні токени кольорів, типографіки, щільності та радіусів.
6. Чотири готові профілі: `Turbo Dark`, `Turbo Light`, `Graphite`, `High Contrast`.
7. Форма завантаження PNG/JPG/WebP до 512 КБ із централізованим відображенням логотипу в CRM shell.
8. Адаптивний екран налаштувань і живий preview основних компонентів.
9. Перевірка доступу: читання через `SETTINGS.READ`, зміна через `SETTINGS.WRITE`.
10. Документація, typecheck, production build, smoke-перевірка та публікація.

### Поза межами релізу

- редагування окремого CSS для кожної сторінки через HTML/JS;
- завантаження довільного SVG без санітизації;
- окремі теми для різних ролей;
- white-label домен, email-шаблони та PDF-шаблони;
- зберігання великих медіа-файлів понад 512 КБ.

## 3. Ролі та права

| Операція | Потрібний дозвіл | Поведінка |
|---|---|---|
| Відкрити «Оформлення» | `SETTINGS.READ` | Перегляд поточного профілю та preview |
| Обрати готовий стиль | `SETTINGS.WRITE` | Застосування та негайне серверне збереження |
| Змінити кольори/типографіку | `SETTINGS.WRITE` | Локальний preview, потім кнопка «Зберегти зміни» |
| Завантажити/видалити логотип | `SETTINGS.WRITE` | Локальний preview, потім серверне збереження |
| Інші CRM-користувачі | Не потрібен доступ до налаштувань | Отримують активний профіль через глобальний bridge |

## 4. UX-вимоги

### 4.1. Заголовок

Екран містить breadcrumb/лейбл «НАЛАШТУВАННЯ · БРЕНД І UI», назву «Оформлення CRM», пояснення «Єдиний стиль для всіх сторінок, ролей і робочих кабінетів», індикатор стану та кнопку «Зберегти зміни».

Стани індикатора:

- «Синхронізовано» — локальні зміни відсутні;
- «Є незбережені зміни» — є зміни, які ще не записані на сервер;
- повідомлення успіху після PUT;
- помилка збереження без втрати поточного draft.

### 4.2. Готові стилі

Картка готового стилю показує мініатюру, назву, короткий опис і стан. Натискання:

1. негайно змінює preview;
2. застосовує профіль до поточної CRM;
3. зберігає профіль через API;
4. показує підтвердження «Стиль застосовано до CRM».

Доступні профілі:

| Профіль | Візуальна ідея | Розмір/щільність |
|---|---|---|
| Turbo Dark | Фірмовий графіт і помаранчевий Turbo LEV | Стандартний |
| Turbo Light | Світла робоча поверхня з помаранчевим акцентом | Стандартний |
| Graphite | Темніший, щільніший інтерфейс для операційної роботи | Компактний |
| High Contrast | Максимальна відмінність тексту, меж і статусів | Комфортний |

### 4.3. Кольори

Редагуються такі токени:

- основний акцент;
- акцент при наведенні;
- фон робочої області;
- фон карток;
- піднята поверхня;
- основний текст;
- другорядний текст;
- межі та розділювачі.

Ввід — native color picker плюс HEX. Сервер приймає лише формат `#RRGGBB`, тому довільний CSS/URL не потрапляє в профіль.

### 4.4. Типографіка й геометрія

Налаштування:

- шрифт: системний, Inter, Manrope;
- режим: темний, світлий, як у системі;
- розмір: компактний 13 px, стандартний 14 px, комфортний 15 px для основного тексту;
- щільність: компактна, стандартна, простора;
- радіус: строгий, стандартний, м’який;
- бічна панель: розгорнута або компактна.

Глобальне правило читабельності: допоміжний текст не менше 11 px, основний текст за замовчуванням 14 px, контрол — 15 px.

### 4.5. Логотип

- приймаються PNG, JPG і WebP;
- максимальний розмір — 512 КБ;
- рекомендовано прозорий фон;
- зображення не розтягується, використовується `object-fit: contain`;
- логотип відображається в глобальній бічній панелі на всіх маршрутах;
- видалення повертає стандартний логотип Turbo LEV;
- SVG навмисно не приймається в цьому релізі через ризик виконання довільного SVG-коду.

## 5. Архітектура застосування

Профіль завантажується в `app/layout.tsx` через `AppearanceThemeBridge`. Bridge:

1. читає останній валідний кеш із `localStorage`;
2. одразу встановлює dataset і CSS-токени на `document.documentElement`;
3. паралельно запитує актуальний профіль через API;
4. оновлює кеш і DOM після відповіді сервера;
5. перераховує режим `auto` після зміни системної теми;
6. синхронізує logo slots у shell.

Таким чином, сторінка не залежить від того, який розділ відкрито, і не має власного локального набору тем.

### 5.1. Семантичні токени

Основний профіль мапиться на наявні CRM-змінні:

| Профільний токен | CRM-токени |
|---|---|
| `background` | `--bg` |
| `panel` | `--panel`, `--surface` |
| `panelRaised` | `--panel-2`, `--panel-raised`, `--surface-muted` |
| `accent` | `--orange`, `--accent` |
| `accentStrong` | `--orange-2`, `--accent-strong` |
| `text` | `--text`, `--foreground`, `--text-primary` |
| `muted` | `--muted`, `--soft-text`, `--text-muted` |
| `line` | `--line`, `--border` |
| `success/warning/danger/info` | `--green/--yellow/--red/--blue` |

Це дозволяє вже мігрованим компонентам змінюватися без правок кожної сторінки. Доданий global override нормалізує body, shell, контролі, фокус, панелі та основні CTA.

## 6. API-контракт

### `GET /api/settings/appearance`

Відповідь:

```json
{
  "ok": true,
  "appearance": {
    "preset": "turbo-dark",
    "themeMode": "dark",
    "accent": "#FF6600",
    "accentStrong": "#FF8A2A",
    "background": "#0B0D10",
    "panel": "#12161B",
    "panelRaised": "#171C22",
    "text": "#F7F7F5",
    "muted": "#8F98A3",
    "line": "#252B33",
    "success": "#2BB673",
    "warning": "#F0B429",
    "danger": "#EF6262",
    "info": "#4F7CFF",
    "font": "system",
    "scale": "standard",
    "density": "standard",
    "radius": "standard",
    "sidebar": "expanded",
    "logoDataUrl": "",
    "logoName": ""
  },
  "updatedAt": null
}
```

### `PUT /api/settings/appearance`

Тіло: `{ "appearance": <CrmAppearance> }`.

Сервер нормалізує enum, HEX, назву логотипу та data URL. Невалідний логотип або розмір понад 512 КБ повертається як HTTP 400. Неавторизований або недостатньо привілейований запис повертається стандартною відповіддю security layer.

Збереження використовує upsert ключа `appearance` у `CrmSetting`, тому окрема міграція БД не потрібна.

## 7. Нефункціональні вимоги

- React/Next.js App Router, без дублювання bridge на сторінках.
- Не блокувати перший paint очікуванням API.
- Не показувати секрети або службові дані в профілі.
- Не дозволяти довільні CSS-значення через API.
- Працювати на ширині від 360 px до desktop.
- Фокус клавіатури має бути видимим і використовувати глобальний акцент.
- Усі елементи керування мають мати текстовий label або доступну назву.
- Після помилки API draft не очищається.
- Застосування профілю не повинно вимагати перезавантаження сторінки.

## 8. План тестування

### Автоматично

- TypeScript typecheck.
- ESLint/доступні lint-скрипти репозиторію.
- Production build Next.js.
- Перевірка route inventory/security gate.

### Smoke вручну/браузером

1. Увійти в CRM і відкрити `Налаштування → Оформлення`.
2. Натиснути кожен готовий стиль і перевірити миттєву зміну preview.
3. Перейти в «Огляд станції», «Клієнти», «Авто», «Діагностика», «Замовлення», «Склад», «Фінанси», «Аналітика» і переконатися, що токени збережені.
4. Змінити HEX, масштаб, щільність, радіус і шрифт; перевірити стан «Є незбережені зміни».
5. Зберегти, оновити сторінку та відкрити CRM в іншій вкладці/сесії.
6. Завантажити валідний логотип, перевірити shell і preview; видалити його та перевірити fallback.
7. Перевірити відхилення SVG, неправильного MIME та файла понад 512 КБ.
8. Перевірити 360 px, 768 px і desktop.
9. Перевірити недоступність PUT для користувача лише з `SETTINGS.READ`.
