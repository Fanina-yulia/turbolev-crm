# ТЗ: CRM-словник безпечного пошуку та черга невідомих термінів

## 1. Мета

Посилити Turbo LEV CRM шаром розпізнавання тотожних назв без зміни діючих сутностей, документів, фінансів, ДК, КП та підбору запчастин.

Система має розуміти варіанти введення на кшталт `рычаг`, `ричаг`, `рьічаг`, `накінечник`, `торможа`, але не повинна автоматично змінювати робочі записи без підтвердження людини.

## 2. Принцип безпеки

CRM-словник є окремим шаром підказок.

Заборонено:
- перейменовувати існуючі послуги, роботи, запчастини або документи;
- автоматично підставляти деталь у КП/ДК/підбір запчастин;
- обходити перевірку VIN, авто, сторони, осі або OE/аналогу;
- змішувати симптом, деталь і роботу в один тип без контексту.

Дозволено:
- показувати підказку у глобальному пошуку;
- зберігати невідомі слова в чергу на ручне опрацювання;
- використовувати канонічну назву як пошукову підказку;
- вести статистику частоти невідомих запитів.

## 3. Обсяг першого етапу

### 3.1. Словник CRM у налаштуваннях

У розділі `Налаштування → Словник CRM` має бути видно:
- кількість канонічних назв;
- кількість синонімів і помилок;
- кількість деталей;
- скільки позицій потребують перевірки сумісності;
- список канонічних назв, категорій і варіантів введення.

### 3.2. Підказки у глобальному пошуку

При введенні слова у глобальному пошуку CRM API `/api/search` має додатково повертати блок `dictionary`.

Приклад:

```json
{
  "dictionary": [
    {
      "canonicalName": "Важіль підвіски",
      "matchedAlias": "рычаг",
      "type": "PART",
      "requiresFitmentCheck": true
    }
  ]
}
```

Цей блок не замінює результати клієнтів, авто, КП, ДК чи записів. Він лише додає підказку.

### 3.3. Черга невідомих термінів

Якщо у глобальному пошуку немає словникового збігу, CRM має записати термін у чергу `crm_dictionary_unknown_terms`.

Для кожного терміна зберігати:
- сирий запит;
- нормалізований запит;
- кількість повторів;
- джерело;
- дату першого виявлення;
- дату останнього виявлення.

Черга потрібна, щоб власник або адміністратор бачив, які слова реально вводять менеджери/механіки, і міг додати їх до словника вручну.

## 4. Критерії приймання

1. `рычаг`, `ричаг`, `рьічаг` розпізнаються як `Важіль підвіски`.
2. `накінечник` розпізнається як `Наконечник рульової тяги`.
3. `торможа` розпізнається як гальмівний блок.
4. Глобальний пошук повертає `dictionary`, але не змінює основні результати.
5. Невідомий термін зберігається в чергу.
6. Черга невідомих термінів відображається в `Налаштування → Словник CRM`.
7. Деталі з ризиком сумісності мають прапорець `requiresFitmentCheck`.
8. TypeScript і smoke-перевірки проходять.

## 5. Не входить у перший етап

- автопідстановка в ДК;
- автопідстановка в КП;
- автоматичний підбір конкретної запчастини;
- міграція бази даних;
- заміна існуючих назв робіт або деталей.

Ці дії мають бути окремими етапами після перевірки першого шару.
