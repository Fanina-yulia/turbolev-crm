# TURBO LEV — Підбір запчастин V7: щільний робочий екран

Дата: 16.09.2026

## Мета
Перетворити `section=parts&diagnosticId=...` з візуально незбалансованого екрану на щільний робочий інтерфейс менеджера запчастин без зміни business logic пошуку, кошика або збереження.

## UI-вимоги
1. Робоча область на desktop: приблизно 28–30% `Деталі до заміни` / 70–72% `Вибрані деталі`. Ліва панель обмежується максимальною шириною близько 460 px, щоб на широких моніторах додатковий простір отримував кошик.
2. Панелі не повинні примусово розтягувати одна одну по висоті. Порожній кошик має бути компактним, а не великим білим полем.
3. `Деталі до заміни` трактуються як компактна черга потреб: назва читається до двох рядків, позиція залишається другорядною, кількість і дія займають мінімально необхідну ширину.
4. Рядок потреби на desktop має бути ущільнений приблизно до 50 px мінімальної висоти; основна дія `підібрати` лишається чіткою компактною кнопкою. Для вже вибраної позиції стан має бути візуально відмінним.
5. Активна потреба має явний акцент; selected/active/hover — різні стани.
6. `ПОТРЕБИ · N` не дублює лічильник прогресу: візуальний акцент переноситься на `Деталі до заміни` + `X/N`.
7. Верхній контекст авто/VIN/клієнта ущільнюється без втрати даних.
8. `Вибрані деталі` є основною робочою поверхнею. Таблиця зберігає всі погоджені 14 колонок і горизонтальний scroll, але отримує максимально можливу ширину під подальше додавання даних про тип результату, постачальника, склад, ETA, сумісність і причину підбору.
9. Disabled `До комерційної пропозиції` не конкурує з основною дією підбору.
10. На екранах <= 1180 px workspace переходить у одну колонку; мобільна логіка V6 не ламається.

## Незмінні правила
- жодних змін API, fitment, pricing, audit, staged selection чи cart persistence;
- усі погоджені колонки кошика залишаються доступними;
- UI font floor >= 11px;
- light/dark theme через чинні CSS variables.
