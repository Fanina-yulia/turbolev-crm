# Бойове ТЗ — компактне бокове меню CRM

## Мета
Зробити desktop-меню компактнішим, стабільним при навігації та повністю функціональним у згорнутому режимі.

## Геометрія
- ширина згорнутої колонки: **56 px**;
- кнопка групи: **36 × 36 px**;
- піктограма групи: **18 × 18 px**;
- активний пункт не повинен збільшувати ширину колонки;
- робоча область не повинна отримувати зайвий лівий відступ після згортання меню.

## Стан меню
- desktop-стан розгортання зберігається окремо від mobile menu;
- вибір користувача зберігається у `localStorage`;
- перехід між розділами, `popstate`, оновлення URL та React rerender не повинні самовільно змінювати стан колонки;
- при переході з однієї сторінки на іншу згорнуте меню залишається згорнутим, розгорнуте — розгорнутим.

## Flyout підпунктів
- у згорнутому режимі клік на кожну групу відкриває flyout праворуч;
- flyout показує всі дозволені RBAC підпункти групи;
- клік на підпункт відкриває саме цей розділ;
- активний розділ підсвічується;
- flyout закривається по Escape, кліку поза ним, зміні групи або навігації;
- прокрутка всередині самого flyout **не повинна закривати його**.

## Налаштування
У групі `Управління` пункт `Налаштування` повинен відкривати всі доступні вкладені розділи:
- Графік;
- Персонал;
- Постачальники;
- Склад;
- Прайс робіт;
- Пости;
- Націнка;
- Каса;
- Інтеграції;
- Камери;
- Шаблони діагностики;
- Оформлення;
- Процеси та статуси;
- Ролі та доступи.

Відображаються лише пункти, дозволені поточній ролі.

## Стабільність і семантика
- іконки груп прив'язуються до семантичного `data-rail-icon`, а не до `nth-child`;
- кожна група має стабільний `data-rail-group-label`, `aria-label` та `title`;
- приховування груп RBAC не повинно змінювати значення іконок інших груп.

## Acceptance criteria
1. Згорнута колонка фактично має 56 px.
2. Іконки візуально менші за попередню версію та мають 18 px.
3. Усі 7 груп відкривають flyout.
4. Кожен дозволений підпункт відкриває правильний CRM-розділ.
5. Усі дозволені вкладки `Налаштування` доступні зі згорнутого меню.
6. Flyout можна прокрутити до нижніх пунктів без його закриття.
7. Після переходів між сторінками стан sidebar не змінюється сам.
8. Після перезавантаження сторінки останній desktop-стан sidebar відновлюється.
9. Mobile layout до 760 px не змінюється.
10. Production build, RBAC/API security і основні CRM smoke-тести проходять без регресій.
