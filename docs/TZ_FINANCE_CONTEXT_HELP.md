# ТЗ: контекстні пояснення фінансових показників

## 1. Мета

Зробити фінансові екрани Turbo LEV самопояснюваними. Користувач повинен розуміти значення фінансового показника без переходу в окрему інструкцію та без знання бухгалтерської термінології.

Scope цієї версії обмежений фінансовими інтерфейсами:
- «Фінансовий центр»;
- «Оплати»;
- «Аналітика → Фінанси».

Інші модулі CRM у цю версію не входять.

## 2. UX-принцип

Біля фінансового терміна відображається компактна іконка «i».

На desktop пояснення відкривається:
- при наведенні курсору на назву терміна;
- при наведенні на «i»;
- при фокусі з клавіатури;
- при натисканні на «i».

На touch/mobile:
- натискання на «i» відкриває пояснення;
- поповер відображається як нижня компактна панель, щоб текст не виходив за межі екрана.

Повторне натискання або натискання поза поповером закриває закріплене пояснення. Escape також закриває його.

## 3. Структура пояснення

Кожен фінансовий tooltip має однакову структуру:

1. Назва показника.
2. «Що це» — коротке пояснення простою українською.
3. «Як рахується» — формула, якщо вона доречна.
4. «Що це означає для СТО» — практичне управлінське значення.
5. «Джерело» — таблиця/факт/агрегат CRM, з якого формується показник.

Пояснення не повинне підміняти сам показник або змінювати його формулу.

## 4. Єдиний словник

Всі пояснення зберігаються централізовано у:

`src/domain/finance-glossary.ts`

Один термін має одне канонічне пояснення незалежно від сторінки.

Заборонено дублювати текст пояснення безпосередньо у JSX різних сторінок.

## 5. Базові терміни

Словник повинен містити щонайменше:
- Гроші зараз;
- Виручка;
- Собівартість;
- Валовий прибуток;
- Валова маржа;
- OPEX;
- Операційний прибуток;
- Чистий прибуток;
- Чиста маржа;
- Cash Flow;
- Надходження;
- Виплати;
- Операційний / інвестиційний / фінансовий Cash Flow;
- Внутрішні перекази;
- Дебіторка;
- Кредиторка;
- Прострочена дебіторка;
- Прострочена кредиторка;
- P&L;
- План / факт;
- Платіжний календар;
- Мінімальний прогноз грошей;
- Точка беззбитковості;
- Прибутковість;
- Оборотний капітал;
- Економіка замовлень;
- Середній чек;
- До отримання;
- Оплачено сьогодні;
- Прострочений борг;
- Сума / Сплачено / Залишок по КП;
- Рахунки та каси.

## 6. Фінансовий центр

Пояснення додаються:
- до всіх головних KPI;
- до ключових заголовків P&L;
- до Cash Flow;
- до дебіторки/кредиторки;
- до точки беззбитковості;
- до прогнозу грошей;
- до прибутковості;
- до рахунків/кас;
- до ключових складових Cash Flow.

Клік по самій KPI-картці продовжує відкривати відповідний розділ. Клік по «i» не повинен запускати навігацію KPI.

## 7. Оплати

Пояснення додаються до:
- «До отримання»;
- «Оплачено сьогодні»;
- «Прострочений борг»;
- «Сума»;
- «Сплачено»;
- «Залишок»;
- суми «До сплати» у вікні проведення оплати.

Пояснення повинні чітко відрізняти касові надходження від P&L-виручки.

## 8. Аналітика → Фінанси

Пояснення додаються тільки до вкладки «Фінанси», без втручання в інші аналітичні вкладки.

Обов’язково пояснюються:
- Доходи P&L;
- Валовий прибуток;
- Чистий прибуток;
- Грошовий потік;
- Дебіторка;
- Кредиторка;
- Економіка замовлень;
- Середній чек;
- Валова маржа;
- Cash Flow;
- Оборотний капітал;
- прострочена дебіторка/кредиторка.

## 9. Візуальні вимоги

- Іконка «i» — 16–18 px.
- Мінімальний текст — 11 px відповідно до UI floor CRM.
- Tooltip не повинен змінювати висоту картки у закритому стані.
- Tooltip має працювати у світлій і темній темі через CSS variables.
- Ширина desktop: до 380 px.
- Mobile: fixed bottom panel з відступом 16 px.
- Z-index має бути достатнім для відображення над картками та таблицями.
- Назва терміна має dotted underline як ненав’язлива підказка, що вона пояснювана.

## 10. Доступність

- «i» має зрозумілий aria-label.
- Popup має role=tooltip.
- Пояснення доступне по focus.
- Escape закриває pinned-пояснення.
- Клік по «i» не повинен запускати батьківську KPI-навігацію.

## 11. Архітектура

Компоненти:
- `src/domain/finance-glossary.ts` — канонічні визначення;
- `app/finance-info-tooltip.tsx` — UI-поведінка;
- `app/finance-info-tooltip.module.css` — стилі.

Фінансові сторінки імпортують тільки `FinanceInfoTooltip` і передають ключ терміна.

## 12. Не входить у scope

- Підказки для СТО/діагностики/запчастин поза фінансовою вкладкою;
- зміна формул фінансів;
- об’єднання API фінансового центру та аналітики;
- перейменування «Оплати» на «Каса»;
- зміна RBAC;
- зміна БД.

Ці питання можуть бути окремими наступними етапами.

## 13. Acceptance criteria

1. Hover на «Cash Flow» показує пояснення.
2. Hover на іконку «i» показує те саме пояснення.
3. Click/tap на «i» закріплює пояснення.
4. Tooltip пояснює різницю Cash Flow і прибутку.
5. «Виручка» пояснює, що це не обов’язково фактичне надходження грошей.
6. «Дебіторка» пояснює, що це не гроші на рахунку.
7. «Внутрішній переказ» пояснює, що він не є доходом/витратою.
8. На «Оплатах» є пояснення KPI і суми/сплачено/залишок.
9. В «Аналітика → Фінанси» пояснення не з’являються в нефінансових вкладках.
10. Клік по «i» всередині клікабельної KPI-картки не виконує навігацію.
11. Mobile popover не виходить за межі viewport.
12. Tooltip працює в dark/light theme.
13. Contract smoke для словника проходить.
14. Production build проходить без TypeScript errors.
