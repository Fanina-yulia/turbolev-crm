# Turbo LEV CRM — Архітектура v0.1

> **Статус: історичний документ першого контуру.** Для поточного аналізу змін, меж модулів, залежностей і smoke-checks використовуйте `docs/CRM-MODULE-MAP.md`, `docs/modules/README.md` та `docs/modules/module-registry.json`. Актуальна модульна карта має пріоритет над старими назвами ролей і переліком модулів нижче.

## Принцип
CRM будується навколо наскрізного маршруту автомобіля, а не навколо окремих довідників. Кожен етап має відповідального, умову входу, наступну дію, блокер і цифровий слід.

## Наскрізний маршрут
LEAD → QUALIFICATION → PREQUOTE → BOOKED → ARRIVED → DIAGNOSTIC_REQUEST → DIAGNOSTICS → PARTS_REVIEW → QUOTE_DRAFT → CLIENT_APPROVAL → PARTS_PAYMENT → PARTS_ORDERED → WAITING_PARTS → READY_FOR_REPAIR → REPAIR → QUALITY_CONTROL → READY → WORK_PAYMENT → PAID → CLOSED → AFTERSALES

## Непорушні правила
1. Замовлення-наряд створюється тільки після підтвердженої діагностики.
2. Діагностика платна незалежно від рішення клієнта щодо ремонту.
3. Деталі не можна замовити до підтвердження оплати клієнтом.
4. Додаткова платна робота створює нову версію калькуляції та вимагає нового погодження.
5. Статус READY неможливий без Quality Control.
6. Видача автомобіля неможлива при balanceDue > 0.
