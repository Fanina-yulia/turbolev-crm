# TURBO LEV — Кабінет механіка: vehicle-first «Мої автомобілі» v1

Дата: 2026-09-17

## Проблема

Головний екран кабінету механіка показував окремий рядок на кожну операцію `WorkOrderLine`. Через це один автомобіль повторювався кілька разів, хоча механіку на цьому рівні потрібно спочатку обрати автомобіль, а вже всередині побачити перелік робіт.

## Ціль

Побудувати навігацію за моделлю:

`Мої автомобілі → один автомобіль = одна картка → деталі автомобіля/роботи`.

## UX-контракт

1. У домашньому блоці замість «Мої роботи» відображається «Мої автомобілі».
2. Для одного держномера одночасно відображається лише один рядок незалежно від кількості призначених операцій.
3. У рядку автомобіля показуються лише ідентичність автомобіля: марка/модель/рік і держномер. Назва операції та статус операції на цьому рівні приховуються.
4. Кнопка «Всі авто» відкриває повний список автомобілів механіка.
5. На екрані повного списку також діє правило «один автомобіль = один рядок».
6. Натискання на автомобіль не створює новий workflow: використовується чинний handler репрезентативної задачі/запису. Далі відкривається наявний екран роботи, де видно операції за ремонтною справою.
7. Ідентичність автомобіля визначається в першу чергу за нормалізованим держномером. Для українських літер, візуально еквівалентних латинським, застосовується канонічне перетворення. Якщо номера немає — fallback на назву автомобіля.
8. Жодних змін у production DB, статусах робіт, API контрактів або фінансових правилах немає.

## Реалізація

- `app/mechanic-vehicle-list-bridge.tsx` — presentation bridge, який групує вже відрендерені рядки за автомобілем і залишає чинні click handlers.
- `app/mechanic-live-cabinet.tsx` — bridge підключено до канонічного кабінету механіка.

## Acceptance criteria

- CHERY AMULET 2007 / AE0916MH з трьома операціями відображається один раз.
- KIA SOUL 2011 / AI1475CO та CHERY AMULET 2007 / AE0916MH відображаються як два окремі автомобілі.
- Натискання на CHERY відкриває чинний detail workflow; список операцій не втрачається.
- TypeScript contract check і CI build проходять.
