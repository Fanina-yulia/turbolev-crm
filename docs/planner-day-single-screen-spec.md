# ТЗ: Планувальник СТО — добовий режим на одному екрані

## Мета
Переробити режим **«План робіт → День · пости»** так, щоб диспетчер бачив увесь робочий день СТО на одному desktop-екрані без вертикального гортання сторінки, з розкладом по постах і кроком 30 хвилин.

## Вихідні принципи
- Не змінювати чинну бізнес-логіку `/api/planner`, `/api/planner/availability` та PATCH `/api/planner/:id`.
- Залишити чинний тижневий режим.
- Використовувати системні theme variables CRM (`--bg`, `--panel`, `--panel-2`, `--line`, `--text`, `--muted`, `--orange`), тому екран має працювати у світлій/темній/auto темі.
- Основний desktop-режим: весь часовий діапазон локації від `openMinute` до `closeMinute` показується в одній горизонтальній шкалі.

## Структура сторінки
1. Header:
   - `TURBO LEV / СТО <локація>`
   - `План робіт`
   - короткий підпис про добовий режим
   - `Сьогодні`
   - `+ Нова заявка`
2. Перемикачі:
   - `День · пости`
   - `Тиждень`
3. Фільтри:
   - локація (якщо їх більше однієї)
   - статус
   - виконавець
   - пост
   - пошук по наряду / клієнту / авто / держномеру / VIN
4. Компактна навігація дати:
   - попередній день
   - поточна дата
   - наступний день
5. KPI доби:
   - записи на сьогодні
   - завершено
   - в роботі
   - очікують
   - кількість вільних 30-хв слотів
   - очікуваний виторг за день
6. Сітка планувальника:
   - ліва sticky-колонка `Пости / ресурси`
   - `Пост 1`, `Пост 2`, …
   - `Без поста / Зона приймання`
   - шкала часу по 30 хв
   - картки записів поверх сітки
   - вільні вікна пунктирними блоками
   - current-time marker для сьогоднішнього дня
7. Легенда статусів під сіткою.

## Картка запису
Мінімально показує:
- час початку / завершення;
- держномер;
- авто;
- короткий опис роботи або клієнта;
- статус.

Клік по картці відкриває чинне редагування запису.

## Рядок ресурсу
Показує:
- колір ресурсу;
- назву поста;
- тип (`Підйомник`, `Яма`, `Розвал-сходження`, `Без підйомника`);
- прогрес завантаження у % за поточний день.

## Вільні вікна
- Дані беруться з чинного `/api/planner/availability`.
- Безперервні інтервали від 60 хв показуються окремими пунктирними блоками `Вільне вікно`.
- Окремі 30-хв слоти залишаються клікабельними в базовій сітці.
- Клік створює нову заявку з передзаповненими датою та часом через чинний event `turbolev:open-new-request`.

## KPI
Розраховуються на клієнті з уже отриманих appointments та availability:
- `Записів` — кількість записів на день без `CANCELLED`.
- `Завершено` — `COMPLETED`.
- `В роботі` — `ARRIVED`, `DIAGNOSTICS`, `IN_REPAIR`, `WAITING_QC`.
- `Очікують` — очікуючі статуси та пауза.
- `Вільні слоти` — кількість доступних 30-хв слотів по постах.
- `Очікуваний виторг` — сума `estimatedAmount` за день.

## Адаптивність
### Desktop
- сітка займає доступну ширину;
- часові колонки стискаються до мінімально читабельної ширини;
- поточна конфігурація СТО (2 пости + зона приймання) повинна вміщатися на одному екрані без вертикального скролу сторінки.

### Середні екрани
- KPI переходять 6 → 3 → 2 колонки;
- часовий grid отримує локальний горизонтальний скрол, якщо ширини недостатньо;
- сторінка не розтягується по ширині.

### Мобільний
- повна одноденна шкала залишається доступною через локальний горизонтальний скрол;
- фільтри стають одноколонковими.

## Acceptance criteria
1. У режимі `День · пости` видно весь робочий день від open до close без горизонтального скролу на стандартному desktop viewport CRM.
2. Для поточної станції з двома постами та зоною приймання план вміщується по висоті одного desktop-екрана.
3. Картки записів відкривають чинний editor.
4. Клік по вільному часу викликає чинний flow `+ Нова заявка` з датою/часом.
5. Фільтри статусу, виконавця, поста та пошуку працюють одночасно.
6. Тижневий режим не змінений функціонально.
7. Light/dark/auto теми не потребують окремих кольорових стилів.
8. Production build проходить без TypeScript/CSS помилок.
