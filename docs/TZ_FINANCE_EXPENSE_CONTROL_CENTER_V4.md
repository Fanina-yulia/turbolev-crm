# TURBO LEV — Фінансовий центр / Витрати V4

Дата: 2026-10-06  
Статус: IMPLEMENTED / CANONICAL

## 1. Канонічна модель

Сторінка «Фінансовий центр → Витрати» не є окремою бухгалтерською книгою. Вона збирає факти з уже канонічних джерел:

- `FinancialEvent` — P&L;
- `CashTransaction` — рух грошей;
- `FinancialObligation` — дебіторка/кредиторка;
- `ExpenseDocument` — ручні первинні витрати;
- `FinancialBudget` — план/факт;
- `InventoryLedgerEntry` / `InventoryBalance` — рух і залишок запчастин;
- `SalaryAccrual` / payroll bridge — зарплата;
- `SupplierOrder` / AP bridge — закупівлі постачальників.

Паралельний ledger заборонений.

## 2. Головне правило

**Cash Flow ≠ P&L ≠ Inventory.**

Закупівля запчастини на склад:
- створює грошовий відтік при оплаті;
- створює/збільшує запас;
- не створює COGS сама по собі.

COGS виникає, коли деталь фактично списана/використана у ремонті або її собівартість визнана в канонічній економіці WorkOrder.

## 3. Вкладки

Expense Control Center містить:
- Усі;
- Операційні;
- Зарплати;
- Запчастини;
- Зобов'язання;
- Бюджет;
- Аналітика.

Для журналу є перемикач:
- «Рух грошей»;
- «Фінрезультат».

## 4. KPI витрат

Expense Center показує:
- усі грошові витрати;
- OPEX;
- зарплати;
- оплату постачальникам;
- собівартість деталей;
- фактичне надходження на склад;
- відкриті зобов'язання;
- операційний результат.

## 5. Запчастини

Окремо показуються:
- оплачено постачальникам;
- оприбутковано на склад;
- списано зі складу у ремонти;
- COGS деталей;
- поточна оцінка складського запасу.

Поточна управлінська оцінка запасу використовує **останню відому фактичну unitCost** для кожного stockKey. Якщо фактичної ціни немає, позиція не вигадується: UI показує, що оцінка запасу занижена.

## 6. Зарплата

Нарахування зарплати і виплата грошей — різні факти:
- нарахування впливає на P&L;
- виплата впливає на Cash Flow;
- невиплачена сума залишається payable.

## 7. Зобов'язання

Відкриті PAYABLE показуються окремо з контролем:
- прострочено;
- до 3 днів;
- до 7 днів;
- до 30 днів.

Часткова оплата не закриває зобов'язання до повного settlement.

## 8. Бюджет і аномалії

Plan/fact використовує `FinancialBudget`.
Expense analytics повторно використовує канонічні finance alerts і completeness checks:
- відсутня собівартість деталі;
- пропущене зарплатне нарахування;
- OPEX growth;
- budget warning / overrun;
- overdue payables.

## 9. Ручні витрати

`ExpenseDocument` залишається первинним реєстром для оренди, комунальних, реклами та інших витрат, які CRM не може сформувати автоматично.

Проведений документ не видаляється. Для виправлення використовується сторно/reversal.

## 10. Безпека

Усі Expense Center read endpoints працюють під `FINANCE_READ`; write-операції — під чинними finance write permissions. Location scope зберігається.

## 11. Контроль регресій

Production build запускає `scripts/finance-expense-center-contract-smoke.ts`.

Smoke не дозволяє випадково:
- змішати purchase з COGS;
- прибрати Cash/P&L перемикач;
- втратити inventory receipt/issue distinction;
- прибрати finance access control;
- втратити payroll/supplier bridge source identity.
