# ТЗ: єдиний стандарт шрифтів CRM Turbo LEV

## 1. Обов'язкове правило

Жоден видимий текст інтерфейсу CRM не може мати розмір менше `11px` на desktop, tablet або mobile. Правило поширюється на всі поточні та майбутні сторінки, модальні вікна, drawer-панелі, таблиці, картки, підказки, статуси, форми, кабінети працівників і клієнтський портал.

Єдиний виняток — мікротекст `UA` як декоративна частина зображення номерного знака. Він не є текстом керування та повинен бути явно позначений коментарем у CSS.

## 2. Системна шкала

| Призначення | CSS-змінна | Розмір |
| --- | --- | ---: |
| Абсолютний мінімум | `--crm-font-floor` | `11px` |
| Допоміжний текст | `--crm-font-helper` | `12px` |
| Метадані, коди, статуси | `--crm-font-meta` | `13px` |
| Підписи полів | `--crm-font-label` | `14px` |
| Поля, кнопки, базові контролі | `--crm-font-control` | `15px` |
| Основний текст | `--crm-font-copy` | `16px` |
| Заголовок секції/кроку | `--crm-font-section-title` | `22px` |
| Заголовок сторінки | `--crm-font-page-title` | `30px` |

`11px` дозволено лише для другорядних технічних позначень. Звичайний робочий текст не можна навмисно зменшувати до мінімуму заради розміщення більшої кількості даних — потрібно адаптувати сітку, переносити текст або додавати внутрішній скрол.

## 3. Вимоги до компонентів

- назва роботи, позиції каталогу або рядка таблиці — не менше `13px`;
- код, категорія, ціна, статус і метадані — не менше `12px`, рекомендовано `13px`;
- placeholder, введений текст, select і textarea — не менше `14px`, стандарт `15px`;
- текст кнопок — не менше `14px`, стандарт `15px`;
- пояснення та підказки — не менше `12px`;
- заголовок кроку — не менше `22px`;
- розмір тексту не зменшується в mobile media queries.

## 4. Контроль якості

Скрипт `npm run ui:fonts:check` сканує всі UI-джерела в `app` і `src`. Production build та CI повинні завершуватися помилкою при появі CSS `font-size`/`font`, React `fontSize`, Tailwind arbitrary size або незахищеного відносного розміру нижче системного порога. У CI завжди перевіряється вся кодова база, а не тільки змінені файли.

Перед прийманням змін потрібно виконати:

1. `npm run ui:fonts:check`;
2. TypeScript typecheck;
3. production build;
4. візуальну перевірку desktop, tablet і mobile для змінених екранів.
