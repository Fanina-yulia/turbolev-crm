# TURBO LEV — компактне робоче вікно запису в Планувальнику

## Мета
Робоче вікно запису має повністю вміщуватися в один desktop-екран без вертикальної прокрутки за типової висоти viewport 768 px і містити лише інформацію, потрібну для оперативної роботи.

## Обов’язкові дані
- автомобіль, держномер та перехід у картку авто;
- клієнт, телефон та перехід у картку клієнта;
- дата/час і тривалість;
- пост;
- механік;
- завдання/діагностика/роботи;
- орієнтовна сума діагностики або робіт;
- поточний сервісний статус.

## Прибираємо з робочого вікна
- окремий великий блок «Фінанси»;
- дубльований блок «Стан роботи» з timeline;
- службовий readonly-блок з поясненнями;
- дублюючий footer з кнопкою карти авто (перехід уже є у верхньому блоці).

## Орієнтовна сума
Джерело — `ServiceAppointment.estimatedAmount`, що вже заповнюється з `preliminaryAmount` при створенні запису. Це не фінальна сума до сплати і не залежить від сформованого фінансового документа.

- `purpose=DIAGNOSTICS`: «Орієнтовна вартість діагностики»;
- `purpose=REPAIR`: «Орієнтовна сума робіт»;
- якщо сума ще не розрахована: «Ще не розраховано».

## Клієнт
`clientId` додається до Planner API contract. Натискання на ім’я/блок клієнта відкриває `Клієнти` з `clientId`. Якщо `clientId` відсутній, блок залишається неінтерактивним.

## Acceptance
1. Типове робоче вікно не має власної вертикальної прокрутки на desktop 1366×768 та вище.
2. Орієнтовна сума показується навіть коли `payment.amount` ще не сформований.
3. Клік по клієнту з `clientId` відкриває картку саме цього клієнта.
4. Клік по авто продовжує відкривати картку авто.
5. Редагування дати/часу, поста, механіка та завдання зберігається.
6. API/parser не губить `clientId`.
