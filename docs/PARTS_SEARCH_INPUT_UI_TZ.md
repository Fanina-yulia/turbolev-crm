# TURBO LEV CRM — ТЗ: візуальне оформлення поля пошуку деталей

## 1. Мета
Привести поле пошуку в модулі підбору деталей до єдиної візуальної системи TURBO LEV CRM та усунути «чужий»/світлий вигляд введених або автоматично підставлених браузером даних.

## 2. Проблема
Після введення або автозаповнення значення поле пошуку могло візуально вибиватися з темної теми CRM: браузерний autofill додавав власний фон/колір тексту, а кнопка очищення виглядала нерівно відносно рядка введення.

## 3. Область змін
Сторінка підбору деталей (`app/parts-catalog.tsx`) та її стилі (`app/parts-catalog.module.css`).

Зміни не повинні впливати на:
- алгоритм пошуку деталей;
- API BM Parts / Юнік Трейд та інші інтегровані джерела;
- VIN/OEM/аналогову логіку;
- додавання знайденої пропозиції до кошика;
- блоки «Кошик» і «Підсумок»;
- розрахунок закупівельної/продажної ціни та націнки.

## 4. Функціональні вимоги
1. Введене користувачем значення залишається всередині поля та не змінює його геометрію.
2. Browser autofill не повинен підміняти темний фон поля білим/жовтим системним фоном.
3. Колір тексту після autofill має відповідати `var(--text)` CRM.
4. Каретка введення має бути видимою та відповідати основному кольору тексту.
5. При виділенні тексту використовується акцент TURBO LEV, а не системне оформлення, що конфліктує з темою.
6. При фокусі блок пошуку зберігає темну поверхню CRM.
7. Кнопка очищення `×` має бути компактною, відцентрована по вертикалі та горизонталі, без зміщення висоти поля.
8. Очищення поля не повинно змінювати існуючу React-логіку: натискання `×` встановлює значення фільтра у порожній рядок.
9. Компонент повинен лишатися адаптивним у чинних breakpoint сторінки.

## 5. Візуальні вимоги
- темний фон відповідно до `--parts-surface-soft`/чинної теми;
- текст — `--text`;
- акцент — `--orange`;
- відсутність браузерних outline/background артефактів;
- однакова висота поля до і після введення/автозаповнення;
- кнопка очищення орієнтовно 22×24 px і не розтягує контейнер.

## 6. Технічна реалізація
У `app/parts-catalog.module.css`:
- для `.partSearch input` вимкнути нативний `appearance`, лишити прозорий фон, зафіксувати текст/каретку у кольорах CRM;
- додати стилізацію `::selection` через акцентний колір;
- для `:-webkit-autofill` та його станів `hover/focus/active` примусово задати `-webkit-text-fill-color`, inset box-shadow у кольорі поверхні CRM та caret-color;
- для `.partSearch:focus-within` зберігати поверхню `var(--parts-surface-soft)`;
- `.partSearch button` центрувати через CSS Grid і зафіксувати компактні розміри.

## 7. Acceptance criteria
Задача прийнята, якщо одночасно виконуються умови:
1. У Chrome/Edge після ручного введення поле не світлішає і не змінює висоту.
2. Після browser autofill поле залишається в темній темі CRM.
3. Текст, каретка та виділення читабельні.
4. `×` рівно центрований і очищає поле одним натисканням.
5. Візуально поле не конфліктує з сусідніми блоками підбору деталей.
6. Пошук, фільтрація та кошик працюють як до зміни.
7. На ширинах desktop/tablet/mobile чинна сітка сторінки не ламається.
